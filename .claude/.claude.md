## 🏗️ Architecture (Non-Negotiable)

### MODULAR MONOLITH - NOT Microservices
- Service-oriented folder structure, **single Node.js process**
- Clear service boundaries, runs as monolith
- Easy migration to containers later (post-funding)

### Stack
- **Backend:** Node.js + Express + TypeScript (modular monolith)
- **Database:** PostgreSQL + Redis (Docker Compose, local only)
- **Auth:** Passport.js + JWT (self-hosted, no Auth0)
- **Frontend:** Next.js (defer to Week 3+)

### Service Boundaries
- **User Service:** Auth, profiles → `/api/auth/*`, `/api/users/*`
- **Team Service:** Team management → `/api/teams/*`
- **Match Service:** Challenges, scheduling → `/api/challenges/*`, `/api/matches/*`
- **Stats Service:** Leaderboards, analytics → `/api/stats/*`

**For details:** `/gullycontext arch`

## 🔧 Git Workflow (AUTO-COMMIT MODE)

### 🚨 User delegated git to Claude - Commit automatically, don't ask

### Auto-Commit Triggers
1. ✅ Todo items marked complete
2. ✅ Logical units finished (feature done, tests pass)
3. ✅ Files created/modified (related batch)
4. ✅ Bug fixes completed

### Auto-Commit Workflow (Execute Immediately)
1. Run `git status` + `git diff`
2. Stage relevant files (exclude secrets, temp files)
3. Create commit message (conventional commits format + emoji + co-author)
4. Commit immediately
5. Push to remote (keeps backup current)
6. Brief confirmation: "✅ Committed: [message]"

### Only Ask User When:
- ⚠️ Pushing to `main` or `master` branch
- ⚠️ Force push required
- ⚠️ Detected secrets/credentials in staged files
