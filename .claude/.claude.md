**Session Startup:**
1. Check task status via SlashCommand tool (gullystatus) → reads CSV, identifies pending work
2. Confirm task with user
3. Update CSV: `status=in_progress`, `started=YYYY-MM-DD`

**Completing Task:**
- Update CSV: `status=completed`, `completed=YYYY-MM-DD`, `test_count=N`, `notes=summary`
- Commit CSV with task completion

**Validation:**
- ALWAYS check status at session start using SlashCommand tool
- NEVER assume task status from memory
- ALWAYS update CSV when completing tasks

## 🚨 FILE BUDGET LIMITS (HOOK-ENFORCED)

**Every file in .claude/ loads at EVERY session = $$$ cost**

**Before writing docs/commands**: Check `.claude/FILE_BUDGETS.json` for limits. Hook auto-enforces.

**Strict limits** (writes BLOCKED if exceeded):
- `.claude/commands/*.md`: 30 lines (logic only, NO examples)
- `.claude/agents/*.md`: 150 lines (instructions only, NO background)
- `.claude/.claude.md`: 200 lines (this file)
- `docs/sessions/*.md`: 50 lines (use `/gullycondense`)

**Rule**: If it doesn't need to load every session → move to `docs/`

**Directory Rules:**
- Project docs → `/docs/`
- Context (on-demand) → `/docs/context/`
- Agent prompts → `/.claude/agents/` (concise) | verbose → `/docs/agents/`
- Commands → `/.claude/commands/` (concise) | docs → `/docs/commands/`

**Hook blocks violations.** Emergency bypass: `CLAUDE_HOOK_BYPASS=1` (rare only)
