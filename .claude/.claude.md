## 🏗️ Architecture (Non-Negotiable)

### MODULAR MONOLITH - NOT Microservices
- Service-oriented folder structure, **single Node.js process**
- Clear service boundaries, runs as monolith
- Easy migration to containers later (post-funding)

### Stack
- **Backend:** Node.js + Express + TypeScript (modular monolith)
- **Database:** PostgreSQL + Redis (Docker Compose, local only)
- **Auth:** Passport.js + JWT (self-hosted, no Auth0)
- **Frontend:** Next.js (defer to Week 3+)

### Service Boundaries
- **User Service:** Auth, profiles → `/api/auth/*`, `/api/users/*`
- **Team Service:** Team management → `/api/teams/*`
- **Match Service:** Challenges, scheduling → `/api/challenges/*`, `/api/matches/*`
- **Stats Service:** Leaderboards, analytics → `/api/stats/*`

**For details:** `/gullycontext arch`

## 📚 Phase 1 Learnings - Mistake Prevention

### ✅ Always Verify Immediately
- Run full test suite after changes (not just individual tests)
- Run `npm run build` before committing
- Check container logs after config changes

### ✅ Common Pitfalls to Avoid
1. **Config files**: Don't use empty strings for password fields (Redis, etc.)

- Manageable task chunks (feature-driven)
